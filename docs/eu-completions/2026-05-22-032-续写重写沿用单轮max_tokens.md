# 续写 / 重写沿用当前单轮 max_tokens

## 任务

续写、重新生成、自动续写嵌套请求不再按旧「字符控制目标」（如 500 tk）把 `max_tokens` 压到约 560；统一使用当前 liveProfile 单轮上限（默认 2048）。

## 改动

- `public/eu.html`（v117）
  - 新增 `euApplyLiveProfileMaxTokens(stPayload, liveProfile)`。
  - 移除 `euApplyAutoContinueMaxTokens`、`euRemainingAutoContinueTokens` 及 `maxReplyTokensOverride` 传参。
  - `requestAiReply` / `requestAiReplyStream`、流式首轮自动续写嵌套、手动续写、重新生成均走 `euApplyLiveProfileMaxTokens`。

## 说明

- **自动续写「目标 token」**仍用于判断是否发起第二轮请求（`shouldAutoContinueReply`），不改变单次 API `max_tokens`。
- `buildAutoContinueSystemMessage` 里的「本条须在 N–M token」提示仍存在；若需去掉可另开任务。

## 自测

1. 硬刷新 `eu.html?v=117`。
2. 开自动续写或点「续写」「重新生成」，Network 里 `max_tokens` 应为 **2048**（或预设更大且在 cap 内），而非 ~560。
