# EU 对齐「绑定预设到连接」与全局 API 字段

## 现象

用户坚持酒馆主界面一直使用 xAI / Grok，但 EU 请求仍触发 `OpenAI API key is missing`。

## 原因

酒馆在未勾选 **绑定预设到连接（bind_preset_to_connection）** 时，切换预设**不会**用预设文件里的连接项覆盖当前会话的全局 `oai_settings`（见 `public/scripts/openai.js` → `onSettingsPresetChange` 中对 `isConnection` 且 `!bind_preset_to_connection` 的跳过逻辑）。

EU 的 `fetchStLiveGenerationProfile` 原先优先使用 **预设 JSON** 里的 `chat_completion_source`，若预设文件仍保存旧的 `openai`，就会与主界面实际使用的全局 **`settings.json` 根级字段** 不一致。

## 改动

- `public/eu-demo.html`  
  - `EU_OPENAI_CONN_OVERLAY_KEYS` + `euMergeOpenAiPresetWithLiveConnection`：当 `bind_preset_to_connection` 为假时，用全局 `rawSettings` 中非空的连接相关字段覆盖预设副本后再解析 `chat_completion_source`、模型与各 URL。  
  - `fetchStLiveGenerationProfile` 全程使用合并后的 `mergedPreset`。  
  - 更新 `EU_CLIENT_BUILD_STAMP`。

## 用户侧

硬刷新 EU；若仍异常，在酒馆 **保存一次设置**（确保全局 `chat_completion_source` 写入磁盘）。
