# 2026-05-01-024 EU 设置页 max_tokens 覆盖开关

## 任务

在不再使用多轮 `ensureReplyMinTokens` 的前提下，提供与「酒馆里目标输出量」同类的**单次 completion 上限**控制：开关 + 数值，仅覆盖发往 `/api/backends/chat-completions/generate` 的 `max_tokens`。

## 行为

- **默认关闭**：`max_tokens` 仍来自 `fetchStLiveGenerationProfile` 读取的当前酒馆预设 `openai_max_tokens`（与此前对齐逻辑一致）。
- **开启**：在 320～2000 范围内使用设置页中的 **目标 max_tokens**，通过 `applyEuReplyMaxTokensToProfile` 在读取预设后覆盖；**不**发起多轮补长。
- 保存设置时清空 `stLiveConfigCache`，使新上限立即生效。
- 世界聊天状态条与 `getEuFeatureProbe` 反映当前是否覆盖及数值。

## 改动路径

- `public/eu-demo.html`（`EU_CLIENT_BUILD_STAMP` → `20260501-024`）

## 自测

1. 设置 → 关闭覆盖：发一条消息，探针 / 抓包中 `max_tokens` 应与酒馆预设一致。  
2. 开启覆盖并设为例如 1200：抓包 `max_tokens` 应为 1200。  
3. 与酒馆「用户设置 → 自动续写 → 目标长度」仍为不同概念：此处仅 **OpenAI 风格单次 max_tokens**，不实现酒馆 UI 的 auto-continue 触发逻辑。
