# 恢复 16K 上下文与 2048 单轮上限

## 问题

用户曾按 `2026-05-20-015/016` 将默认改为 **16383 上下文**、**2048 max_tokens**，但实际仍见 8192 / 2000。

## 根因

1. **代码回退**：后续改动把 `eu.html` 又改回 `contextTokens: 8192`、`Math.min(2000, max_tokens)`，删掉了 `normalizeEuReplyMaxTokens`。
2. **EU 不用预设上下文**：故事书 `max_context` 来自 **EU 设置 → runtimePrefs**（localStorage），**不读**预设 `openai_max_context`（即便 JSON 已是 16383）。
3. **浏览器旧缓存**：localStorage 里若仍是 8192，界面一直显示 8192，直到迁移或手动保存。
4. **自动续写**：开启后单轮 `max_tokens` 会按目标 token（默认 500）收紧，与 2048 无关。

## 修复（`public/eu.html` v116）

- `EU_DEFAULT_CONTEXT_TOKENS = 16383`，未解锁上限 `16383`（非 12288）。
- `normalizeEuReplyMaxTokens`：单轮 **2048～8192**，去掉 2000 硬顶。
- `loadRuntimePrefs`：曾保存 **8192** 的一次性升到 **16383**（`__ctx16383` 标记）。
- 设置滑块默认/最大值与状态条对齐 16383。

## 自测

1. 硬刷新 `eu.html`（构建戳 `20260522-context-16k-reply-2048-v116`）。
2. 聊天区状态条应 **上下文16383**；`getEuAlignmentProbes().slice(-1)[0].payloadMaxTokens` 在续写关时应 **≥2048**。
3. EU 设置 → 保存设置；若仍 8192，点保存或清 `eu_demo_runtime_prefs_*` 后重进。

## 酒馆主站

`data/wohenziliao/settings.json` 若仍为 `max_context: 8192`，需在 `index.html` OpenAI 预设里单独调到 16383（EU 故事书不读该项）。
