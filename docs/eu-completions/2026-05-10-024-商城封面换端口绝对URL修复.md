# 商城卡片图换端口后丢失 — 原因与修复

## 原因

封面字段 `img` 若被存成 **带端口的全局 URL**（例如 `http://127.0.0.1:8000/user/images/...`），换端口后浏览器仍向 **8000** 请求图片；旧端口未监听时，商城与「已获取」里同一 `img` 引用全部失效。

此前 `normalizeStoredImagePath` 对任意 `http(s)://` 一律原样保留，未把「本机环回 + 酒馆资源路径」压成 **`/user/...` 相对路径**。

另：**浏览器存储配额**触顶时，EU 会把大图换成 SVG 占位（`buildTinyCoverDataUrl`），看起来像「图没了」——与换端口无关；控制台曾有配额相关 toast。

## 代码改动

- `public/eu-demo.html`
  - 新增 `loopbackStImageAbsoluteUrlToPath`，在 `normalizeStoredImagePath` 中把 `127.0.0.1` / `localhost` / `0.0.0.0` / `[::1]` 上且路径为 `/user/`、`/api/`、`/characters/`、`/backgrounds/` 的绝对 URL 改为同源相对路径。
  - 启动时若 `eu_demo_dev_items` 的 JSON 串里仍含上述坏 URL，自动 `persistDevItems({ skipMigrate: true })` 写回已规范化数据，避免每次刷新都依赖内存修正。
  - 更新 `EU_CLIENT_BUILD_STAMP`。

## 删除旧端口数据（用户操作）

在确认新端口下商城图正常后，于 Chrome **Application → Local Storage** 选中 **旧 origin**（如 `http://127.0.0.1:8000`），右键 **Clear**，或逐项删 `eu_demo_*` 键。EU 无法从脚本跨站删其它 origin 的数据。
