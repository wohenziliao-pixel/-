# 故事书「目标长度」联动单轮 max_tokens（方案 2）

> **已由 `20260508-050` 废止**：与酒馆 `shouldAutoContinue` 对齐后，目标不再改写单轮 `max_tokens`。见 `2026-05-10-004-自动续写对齐酒馆shouldAutoContinue.md`。

## 目标

在**不改变**提示词拼装、续写触发条件、合并与后处理的前提下，让「新增规则」里填写的目标 Token 同时约束**每一轮**发往 SillyTavern 的 `max_tokens`，与酒馆主界面「单轮输出上限」语义对齐。

## 行为

- 条件：`getActiveStorybookAutoContinue().enabled === true` 且 `targetTokens > 0`。
- 公式：`stPayload.max_tokens = min(酒馆预设单轮上限, max(64, targetTokens))`。
- 预设上限来自当前 `buildStGeneratePayload` 已写入的 `max_tokens`（与 `/api/settings/get` 一致，含 EU 原有夹取）。
- 流式 `requestAiReplyStream` 与非流式 `requestAiReply` 均在 `assertValidXaiModelOrThrow` 之后应用；若存在 `maxReplyTokensOverride`，仍优先生效。
- UI：「新增规则」弹窗说明与状态栏 `title` 已补充一句。

## 路径

- `public/eu-demo.html`（`applyStorybookTargetMaxTokensToStPayload`，构建戳 `20260508-048`）

## 自测建议

- 酒馆预设 max_tokens 较大时，将目标改为 300，在 Network 或 `[EU-DIFF] request:st.generate` 的 `payloadCore.max_tokens` 中应约为 300。
- 关闭「已启用」或目标填 0：行为与改动前一致（仅用预设）。

## 20260508-049 修订

- `getStorybookAutoContinueForGeneration()`：合并 localStorage 与 `conv.metadata.authorRule.storybookAutoContinue`，避免 cap 判定与状态栏不一致。
- 生效时追加 `[EU-DIFF] request:st.generate.storybook_max_tokens` 便于核对。
- 弹窗说明：目标为**每轮**上限；自动续写最多 3 段拼接，总长可达约 3×。
