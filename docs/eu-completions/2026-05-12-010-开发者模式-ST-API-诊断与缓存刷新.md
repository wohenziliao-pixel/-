# 开发者模式：ST API 诊断与 EU 缓存刷新

## 任务

在 EU 中提供「一键识别 / 对照」酒馆当前 Chat Completion API 配置的能力，避免再次出现「主站已是 xAI/Grok，EU 仍按 OpenAI 解析」等踩坑；优先落在开发者模式而非单独后台页。

## 做了什么

- **`public/eu-demo.html`**
  - 在 `#page-dev` 右侧列表上方增加 **SillyTavern API 诊断** 区块：`刷新诊断`、`清除 EU 缓存并重拉`，结果输出到 `#dev-st-api-diag-out`。
  - 抽出 **`euBuildStGenerationSnapshotFromSettingsGetData`**：与 **`fetchStLiveGenerationProfile`** 共用同一段 `/api/settings/get` 解析与合并逻辑，并生成 `diagnostics`（全局 `oai_settings` 与预设 JSON 的 `chat_completion_source`、合并后、推断后、模型字段、`custom_url` 等）。
  - **`euRunStApiDiagnosticsUi`**：仅拉取并展示，不写缓存。
  - **`euBustStProfileCacheAndRefreshUi`**：清空 `stLiveConfigCache` / `stLiveConfigAt`，用最新 `settings/get` 重建缓存并刷新诊断文案。
  - 更新 **`EU_CLIENT_BUILD_STAMP`** 为 `20260512-dev-st-api-diagnostics`，便于确认静态页已刷新。

## 用户自测

1. 打开 EU 开发者模式页，点击 **刷新诊断**，确认 `effective_chat_completion_source` / `effective_model` 与酒馆当前一致。
2. 在酒馆切换 API 或预设后回到 EU，先点 **清除 EU 缓存并重拉**，再发一条生成，确认不再沿用旧缓存（60s 内原本会走缓存）。
