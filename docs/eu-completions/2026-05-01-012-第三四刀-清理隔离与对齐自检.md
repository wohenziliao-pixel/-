# 任务目标

- 第三刀：将“运行态”与“清理态”进一步隔离，减少清理误伤剧情链路。
- 第四刀：补齐 EU↔ST 对齐自检能力，能直接观察当前发包对齐状态。

# 第三刀（已实施）

1. `syncStorybookContextForConversation()` 改为保守策略：
   - 当暂时找不到故事书时，不再立刻清空 `activeStorybookUid/regexLoaded/storybookScopedSettingUids`；
   - 避免短暂匹配失败把运行态直接抹掉，导致剧情链路断开。

2. `purgeResourceTracesAcrossLocalStorage()` 白名单化：
   - 仅处理明确前缀键：  
     `eu_demo_acquired_items_` / `eu_demo_story_rules_` / `eu_demo_conversations_` / `eu_demo_character_sessions_`
   - 不再通过标题回退删除会话（`chatName` 匹配），仅按 `storybookUid` 精确清理，降低误删。

# 第四刀（已实施）

1. 新增对齐探针缓存：
   - `euAlignmentProbes` + `pushEuAlignmentProbe()`。

2. 新增探针构建：
   - `buildEuAlignmentProbe(stage, payload, messages, liveProfile)`，记录：
     - strict 对齐模式是否开启
     - 故事书绑定是否存在
     - regex 状态/书域设定集数量
     - 消息总数/system 数量
     - payload 的 `max_tokens/source/model`
     - 当前 live preset

3. 在请求链路挂探针：
   - `requestAiReply()` 发包前记录 `non_stream_request`；
   - `requestAiReplyStream()` 发包前记录 `stream_request`。

4. 新增运行自检函数：
   - `runEuStAlignmentSelfCheck()`：检查关键不一致（如 active UID 与会话 UID 不一致、regex 标记异常）。
   - 暴露窗口方法：
     - `window.getEuAlignmentProbes()`
     - `window.runEuStAlignmentSelfCheck()`
