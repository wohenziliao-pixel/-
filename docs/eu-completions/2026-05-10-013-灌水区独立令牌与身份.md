# 灌水区独立令牌与身份（不影响酒馆其它路由）

## 任务

灌水区写操作在代码与鉴权上与酒馆其它 API 解耦：身份可来自酒馆 Cookie 会话，或灌水专用 `X-EU-Tieba-Api` 令牌；令牌签发不经酒馆 CSRF，仅在 `csrf-sync` 的 `skip` 中对 `/api/eu/tieba` 做窄放行。

## 改动

- `src/endpoints/eu-tieba-api-auth.js`（新）：内存令牌表、`issueEuTiebaApiToken` / `revokeEuTiebaApiToken` / `getHandleFromEuTiebaApiToken`、`skipEuTiebaCsrf`。
- `src/server-main.js`：`skipCsrfProtection` 合并 `skipEuTiebaCsrf`；引入上述模块。
- `src/endpoints/eu-tieba.js`：`tiebaBindActorMiddleware`（酒馆 `req.user` 优先，否则令牌→`storage` 用户）；`POST /auth/session`、`POST /auth/logout`；`requireTiebaActor` / `canModerate` / `GET /session` 等统一用 `req.tiebaActorHandle` / `req.tiebaActorUser`；多用户关闭时不签发令牌。
- `config.yaml`：`cors.allowedHeaders` 增加 `X-EU-Tieba-Api`（跨域前端需带该头）。
- `public/eu-demo.html`：`sessionStorage` 存令牌；登录成功后 `POST /api/eu/tieba/auth/session`；`euTiebaMutate` 用于灌水写请求；退出时撤销令牌；`EU_CLIENT_BUILD_STAMP` `20260512-067`。

## 用户自测

1. 开启 `enableUserAccounts`，EU 登录后进入灌水吧：应能发帖/删帖（令牌自动领取）；浏览器无酒馆 CSRF 仅令牌时写操作仍成功。
2. 退出 EU：灌水令牌应失效。
3. 单用户未开多用户：`POST /auth/session` 返回 403，灌水写操作仍依赖原酒馆会话路径。
