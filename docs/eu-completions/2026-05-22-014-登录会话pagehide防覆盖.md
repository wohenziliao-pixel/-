# 登录后会话被 pagehide 空覆盖防护

## 任务

用户反馈重新登录后「我的世界」历史聊天记录消失，需判断是否近期改动导致，并加固持久化逻辑。

## 结论

- **文风恢复 v111**：不读写 `conversationStore`，**不是**主因。
- **游客先体验 v110**：未登录时对话**本来就不保存**；若一直在游客态聊天，登入后看不到那些记录是预期行为。
- **真实风险**：`pagehide` 钩子在「游客清空内存 → 刚设 `currentUser`、云拉取尚未完成」的短窗口内，可能把空的 `conversationStore` 写入 `eu_demo_conversations_<handle>`，覆盖本机已有缓存。游客默认进主站使该路径更易触发。

## 实现

- `pagehide`：游客或未登录不写盘；内存 store 为空且 localStorage 已有 >80 字节会话时跳过写入（与 `persistConversationRuntime` 一致）。
- `enterApp` 异步拉取完成后补一次 `updateWorldSubmenu()`，便于侧栏尽快列出会话。

## 改动

- `public/eu.html`（构建戳 `20260522-login-conv-pagehide-guard-v112`）

## 自测

1. 登录账号聊几句 → 退出 → 再登录，侧栏「我的世界」应仍在。
2. 游客聊几句 → 登入：游客记录仍不应出现；账号旧记录应仍在（若本机/云端未清过）。
3. DevTools → Application → Local Storage 查看 `eu_demo_conversations_<你的handle>` 是否仍为 JSON 对象（非 `{}`）。
