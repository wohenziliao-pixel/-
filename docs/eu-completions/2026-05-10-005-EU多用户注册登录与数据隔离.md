# EU 多用户：真实注册/登录与按用户隔离

## 需求摘要

1. 通过 EU 录入真实账号（写入酒馆用户存储与 `data/<handle>/` 目录）。  
2. 每人独立的会话数据：EU 侧 `localStorage` 已按 `state.currentUser` 分键（会话、商城已购、画像、规则等）；登录后与酒馆 `session.handle` 对齐，API 走该用户目录。

## 服务端

- 新文件 `src/endpoints/eu-auth.js`：`POST /api/eu/register`  
  - 条件：`enableUserAccounts: true` 且 `euPublicRegistration: true`（`default/config.yaml` 已增加项，默认 `false`）。  
  - 限流：每 IP 约 5 次/小时。  
  - 行为：与管理员创建用户一致（`storage` + `ensurePublicDirectoriesExist` + `checkForNewContent` SETTINGS），可选 `email` 字段写入用户对象。  
- `src/server-main.js`：`app.use('/api/eu', euAuthRouter)`（位于 `requireLoginMiddleware` 之前，带 CSRF）。

## EU 前端 `public/eu-demo.html`（build `20260510-051`）

- 登录：`POST /api/users/login` + `credentials: 'include'`，成功后 `enterApp(handle)`。  
- 注册：`POST /api/eu/register`。  
- `ensureStCsrfToken` / `stApiPost` / 流式 generate：`credentials: 'include'`。  
- 登出/切换账号：`POST /api/users/logout` 后清空本地状态与 `stCsrfToken`。  
- 「演示模式」仍为纯前端 `demo_user`，不创建酒馆会话；开启多用户后应使用真实登录以调用 `/api/*`。

## 运维配置（必须）

```yaml
enableUserAccounts: true
euPublicRegistration: true   # 自助注册；公网建议配合 HTTPS + 强密码策略
```

重启 SillyTavern 后生效。

## 自测

1. 改配置 → 重启 → 打开 `eu-demo.html` → 注册 → 用返回的 handle 登录。  
2. 用户 A 购入故事书 → 换账号 B → 商城已购应不同（不同 `eu_demo_acquired_items_<handle>`）。  
3. 酒馆 `data/<handle>/` 下应出现新用户目录。
