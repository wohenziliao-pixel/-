# 续写 / 重新生成：底栏生成状态与气泡定位修复

## 任务

用户点击 ☰ **续写** 仍感觉「没反应」。控制台仅有 cloud push，无报错。

## 根因

1. **视觉错位**：若最后一条是 **用户消息**，续写改的是**上一条 AI 气泡**，三点动画出现在**上方**，底部输入区旁看不到变化，误以为未执行。
2. **缺少全局体感**：仅改气泡内容时，无输入框附近的「生成中」提示（发送时有底栏气泡 + 流式）。
3. 菜单经 `handleChatToolAction` 间接调用，不利于排查；已改为按钮直连 handler。

## 做了什么

`public/eu.html`（构建戳 `20260522-regen-continue-typing-v104`）：

| 改动 | 说明 |
|------|------|
| `#eu-generation-status` | 输入框上方固定显示「续写中… / 重新生成中…」+ 三点动画 |
| `euFindDomChatItemForConvIndex` | 按会话下标定位要更新的 DOM 气泡 |
| `euMountAssistantGenerationBubble` | 支持 `conv` + `convMessageIndex`，并 `scrollIntoView` |
| 按钮 `onclick` | 直连 `handleWorldChatContinue(event)` / `handleWorldChatRegenerate(event)` |
| 控制台 | `[EU] continue: click` / `done` / `failed` |
| 最后一条为用户消息时 | Toast：将为上一条 AI 回复续写 |

## 用户自测

1. **Ctrl+Shift+R** 强刷，构建戳 **v104**
2. 点 ☰ → **续写**：
   - 输入框上方应出现 **「续写中…」+ 三点**
   - 控制台应有 `[EU] continue: click`
   - 目标 AI 气泡应滚动到视野内并显示三点/流式
3. F12 → Network：应有 `chat-completions/generate`

若仍无 `continue: click`，说明点击未进 handler（缓存旧页）；若有点击无 Network，把 Console 全文发回。
