# 2026-05-01-022 刻板句式与删会话误伤收敛

## 任务

1. 排查「每句动作+对白」仍偏刻板的原因并收敛 EU 侧干预。
2. 排查「移除我的世界」仍牵连故事书/商城感知的根因（含是否用了旧静态页/旧 HTML）。
3. 给出可自测的访问方式说明（无法分配公网新 IP）。

## 结论与改动

### 刻板句式

- `EU_STRICT_ST_ALIGNMENT === true` 时，流式首轮之后仍会执行 **`ensureReplyMinTokens`**（多轮补长），且 **`needsContinuation`** 会触发第二次 `requestAiReply`，容易把输出拉成重复结构。
- **修复**：`ensureReplyMinTokens` 在严格对齐下直接返回（不再补长）；流式路径下 **`needsContinuation` 仅在非严格对齐时** 才自动续写。
- **修复**：`buildCompactStorybookDirective` 内对 **`post_history_instructions` 截断至 220 字**，减轻卡内「格式铁律」整段灌入 compact 指令。

### 删会话牵连故事书/商城

- **服务端**：此前已在 `src/endpoints/extensions.js` 的 `deleteConversationFiles` 默认只删 payload 列出的 `.jsonl`，需 **重启 SillyTavern Node** 后生效；若仍用 **`稳定对话版.html` / `single-stable.html` / `单机稳定版.html`**，其 `doDelete` **不调** `deleteConversationFiles`，行为与 `eu-demo.html` 不一致。
- **客户端**：`removeConversationRuntime` 曾按故事书 UID **级联删除同书下全部本地会话**，侧栏移除时 **`openDeleteConversationModal` 未传 `convKey`**，易触发整书清空，看起来像故事书/商城异常。
- **修复**：移除该级联，**只删当前会话键**（或按角色名回退匹配）；侧栏 × 按钮传入 **`sessionKey`**（来自 `characterSessions`）。

### 如何确认不是旧 WEB

- 页面增加 **`EU_CLIENT_BUILD_STAMP = '20260501-022'`**，`DOMContentLoaded` 时写入 **`document.documentElement.dataset.euClientBuild`** 并在控制台打印 `[次元姬 EU] client build …`。
- `<head>` 增加 **no-cache** meta，减少浏览器强缓存旧 `eu-demo.html`。

## 用户自测

1. **务必**打开 `http://<你的主机>:<端口>/eu-demo.html`（不要用稳定版三文件测删盘逻辑）。
2. DevTools → Network → **Disable cache**，硬刷新；控制台应看到 **client build `20260501-022`**；或执行：`document.documentElement.dataset.euClientBuild`。
3. 修改服务端后 **重启 Node**，再删「我的世界」一条会话：故事书列表与商城条目应仍在；仅该条会话从侧栏消失。
4. 观察回复是否仍句句「动作+对白」：若仍明显，多半来自 **角色卡 `mes_example` / 模型习惯**，可再缩卡或换模型对比。
