# 任务目标

- 调整“删除”语义：用户侧不能删除商城公用资源，只能移除自己“我的世界”中的资源引用。
- 保证书间隔离：移除某本书时，联动清理该用户在该书下的聊天记录、后端聊天文件清理请求与规则缓存，避免污染。

# 实施内容

1. 在 `public/eu-demo.html` 中强化故事书规则键隔离逻辑：
   - `getStoryRuleBookKey()` 在仅有标题时会尝试反查已获取故事书 UID，优先用 UID 作为规则存储键，减少同名/跨书污染。
   - 新增 `clearStorybookRulesByBook()`，支持按 `storybookUid/storybookTitle` 定向清理规则缓存。

2. 新增按故事书批量清理当前用户会话的方法：
   - 增加 `removeConversationRuntimeByStorybook(storybookUid, storybookTitle)`，清理前端 `conversationStore/characterSessions` 中该书相关会话并持久化。

3. 重定义用户侧删除行为（原 `deleteDevItem`）：
   - 改为“移出我的世界”，不再删除 `devItems` 公用资源定义。
   - 从当前用户 `eu_demo_acquired_items_*` 中移除对应资源 UID（用户标记清理）。
   - 若是故事书资源，联动：
     - 清理该用户该书会话（前端）；
     - 异步请求后端执行 `deleteConversationFiles`（本地聊天文件/备份清理）；
     - 清理该书规则缓存；
     - 若正处于该书会话，重置当前书绑定状态。

4. UI 文案同步：
   - 资源操作按钮由“删除”改为“移出我的世界”，避免与“删除公用商品”混淆。

# 用户自测建议

- 在“我的世界”移出某本故事书后，确认：
  - 商城仍可见该商品（公用资源未删）；
  - 该用户故事会话在前端消失；
  - 对应后端聊天文件被清理（若服务端可用）；
  - 该书“新增规则”不再残留。
