# EU 续写机制核查与生效条件

## 任务

用户要求：**不动网络版酒馆**（仅作后台）；检查 **EU** 内「续写」是否生效。

## 结论

EU 续写逻辑**在代码里是接通的**，分两种模式：

| 类型 | 入口 | 是否默认开启 |
|------|------|----------------|
| **自动续写**（字控） | 对话 ☰ → **新增规则** →「已启用」+ 目标 Token | **默认关闭**（`enabled: false`） |
| **手动续写（用户所问）** | 左下角 **☰** 菜单最底 **「续写」**（`handleChatToolAction('continue')`） | **不依赖**字控开关 |

### 手动「续写」按钮（☰ 最底下）

接线：`#chat-tools-trigger` → `handleWorldChatContinue` → `EUAdapter.continueLastAssistant`。

生效条件：

1. 当前在 **故事书对话页**（`#page-world-chat.active`），否则 Toast「请在故事书对话中使用续写」
2. 有活跃会话
3. 会话里存在 **assistant** 消息且 `content` 非空（若最后一条是你刚发的 user，会续写**上一条** AI 气泡）
4. 未与其它操作并发（`worldMessageActionBusy`）

行为：调用 `requestAiReply`（续写提示词），把返回片段 `mergeContinuationReply` **合并进同一条** assistant，再 `openWorldChat` 刷新；**不会**新增用户气泡。

失败时可见：系统气泡「续写结果为空 / 合并后为空」，或 Toast「续写失败：…」。

与字控无关：即使「已启用」未勾选，手动续写仍会发 API；仅第二轮自动嵌套续写才受 `canEuAutoContinueSecondRequest` 限制。

`EU_STRICT_ST_ALIGNMENT = true` **没有关掉**自动续写第二轮请求，只关闭了 EU 侧的「补长 / 强制改中文 / regenerateDialogue」等后处理。

## 自动续写触发条件（`shouldAutoContinueReply`）

须同时满足：

1. `getStorybookAutoContinueForGeneration()` → `enabled` 且 `allowChatCompletions`
2. 目标 Token > 0（如 500 → 合格区间约 **440–560** 估算 token）
3. 当前整条 AI 正文估算 token **< minTokens（目标的 88%）** → 必续写；或在 min–target 之间且 `looksReplyIncomplete`（未以句号等收束）
4. 嵌套深度 `< 2`（最多再请求约 2 轮）
5. **非开场白**（开场白直接 push，不走 `requestAiReply` 续写链）

流式主路径：首轮 `requestAiReplyStream` 结束后在 `EUAdapter.send` 内单独判断并 `requestAiReply` 续写一轮（约 8148–8165 行）。

## 常见「感觉没续写」原因

1. **未勾选「已启用」**（最常见）
2. 估算 token 已在目标上限以上（如目标 500 但已 ≥560）
3. 正文较短但以 `。！？` 结尾 → `looksReplyIncomplete` 为 false，不再自动续写
4. 续写 API 失败或 `mergeContinuationReply` 剥掉重叠后为空
5. 流式超时走 **fallback 非流式**（8192 起）时**未再做**流式那段续写判断（边缘情况）
6. 浏览器缓存旧 `eu.html`（构建戳非当前）

## 自测步骤（用户）

1. 打开 EU 对话，看输入框上方状态条：`续写：开·XXXtk` 或 `续写：关`
2. ☰ → **新增规则**：勾选 **已启用**，目标如 **900**，保存
3. 发一条**新消息**（非开场白），F12 → Network 是否出现 **第二次** `POST .../api/backends/chat-completions/generate`
4. ☰ → **续写**：上一条为 AI 时应合并进同一条气泡；失败会有 Toast

控制台：`document.documentElement.dataset.euClientBuild` 应对应当前部署戳。
