# 对话云 push ok 但刷新仍无保存（v94）

## 现象（v93）

- 浏览器已是 v93，`conversation cloud push ok` 多次出现。
- 刷新/重登后聊天记录仍丢，或服务器 `check` 仍为 2 字节。

## 根因

1. **服务端 clearedAt 锁**：SSH/清理后磁盘 `resume` 带 `clearedAt`，v93 虽允许部分新会话上传，但判定依赖 `cloudAt > cleared`；边界情况下 **conversations / sessions 被 skip**，客户端仍可能误判为成功。
2. **锁未解除**：即使 resume 写入成功，磁盘 `clearedAt` 未清除时，下次登录 `pull` 仍按「云端已清理」处理，覆盖本机。
3. **push ok 误导**：此前未校验响应 `savedKeys` 是否含 `eu_demo_conversations_*`。

## 修复（v94）

- 服务端 `incomingIsNewSessionAfterServerClear`：新会话（非空 conv + resume 无 clearedAt + 有会话目标）三键一律放行。
- 服务端 `unlockServerClearLockOnMergedResume`：成功写入非空 conv 后删除磁盘 resume 的 `clearedAt`。
- 客户端推送前 `euNormalizeResumeBeforeConversationCloudPush` 去掉本机 `clearedAt`。
- `euPushConversationCloudNow` 仅在 `savedKeys` 含 conversations 时记 push ok，否则 `conv_not_saved` 警告。

构建戳：`20260520-conversation-cloud-unlock-clear-v94`
