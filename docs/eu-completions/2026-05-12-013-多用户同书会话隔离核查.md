# 多用户、同一故事书：会话是否串联（代码核查结论）

## 核查范围

`public/eu-demo.html` 中会话存储、`ensureConversationForCharacter`、`startStorybookChat`、商城「已获取」与 dev 商城数据源。

## 结论摘要

| 维度 | 是否独立 | 说明 |
|------|------------|------|
| **操作系统进程** | 否 | EU 为单页应用（SPA），一个标签页一条 JS 运行时，不是每用户独立进程。 |
| **不同登录账号（不同 `state.currentUser`）** | 会话与已获取列表 **隔离** | `localStorage` 键均带 `userKey`，如 `eu_demo_conversations_${userKey}`、`eu_demo_acquired_items_${userKey}`、`eu_demo_character_sessions_${userKey}` 等。 |
| **同一故事书 `storybookUid`** | 定义共享、**聊天记录不共享** | 卡面/故事书条目来自全局 `eu_demo_dev_items`（开发者导入库，**不按用户分仓**）；两人各自 `conversationStore` 中 `messages` 独立，`metadata.storybookUid` 仅指向同一本书的 uid。 |
| **同账号、多标签页** | 存在 **竞态** 风险 | 共享同一 `localStorage` 与同一套内存 `state`，多标签同时写会话时可能出现「后写覆盖」，不属于「两人对话串进一条线程」，但属于多窗口一致性需注意。 |
| **SillyTavern 后端** | 另议 | 若多用户共用同一浏览器里的酒馆登录与 Cookie，酒馆侧聊天上下文会共用，与 EU 的 localStorage 隔离无关。 |

## 关键代码依据

- `getConversationStoreKey()` → `eu_demo_conversations_${state.currentUser || 'guest'}`
- `getAcquiredSet()` / `persistAcquiredSet` → `eu_demo_acquired_items_${userKey}`
- `buildConversationKey` 含时间戳与随机串，同角色名也会得到 **不同 `convKey`**
- `startStorybookChat` 将 `conv.metadata.storybookUid` 设为该书 uid，消息仍在该用户自己的 `conversationStore[convKey].messages` 中
