# 温柔风 generate 401 与 GLM 密钥绑定修复

## 任务

用户本机 `eu.html` 发消息时出现「对话服务暂时不可用」，DevTools 中 `POST /api/backends/chat-completions/generate` 为 **401**；控制台有 `[EU] custom secret rotate GLM5.1` 类日志。需定位根因并加固 custom 文风密钥切换。

## 根因

1. **上游 API 密钥无效或拿错密钥**：温柔风走 `custom` + 智谱 `bigmodel.cn`；创意风走 Venice。全局仅一条「当前激活」的 `api_key_custom`，若发消息前未 `rotate` 到对应 profile 的密钥，上游常返回 401（ST 流式转发时浏览器侧可能仍显示 401/400）。
2. **GLM5.1 连接 profile 未保存 `secret-id`**：本机 `data/wohenziliao/settings.json` 中 `VENICE` 有 `secret-id`，`GLM5.1` 仅有 `exclude` 含 `secret-id` 但**无顶层绑定**，`euActivateCustomSecretForWritingStyle` 原先静默 `return`，轮换未执行。
3. 控制台 `custom secret rotate GLM5.1` 多为 **catch 分支**（轮换请求异常），非成功日志。

## 改动

| 路径 | 说明 |
|------|------|
| `public/eu.html` | 新增 `euRefreshCustomSecretsReadCache`、`euResolveConnectionProfileSecretId`（按连接名/密钥标签模糊匹配）；`euActivateCustomSecretForWritingStyle` 使用 `stApiPost` 轮换、成功打 `rotate ok`、生成前 `strict` 缺密钥则用户可见报错；`validateEuWritingStyleGenerationRoute` 校验 custom 已绑定密钥；流式 400/401 时刷新配置并重试一轮；构建戳 `20260522-custom-secret-resolve-v125` |

## 用户自测

1. 硬刷新 `eu.html`，控制台应见 `client build 20260522-custom-secret-resolve-v125`。
2. 在酒馆 **Connection Manager** 为 **GLM5.1** 填写并保存 **Custom API Key**（与 VENICE 一样会出现 `secret-id`）；或在 Secrets 里为 Custom 密钥标签命名为 `GLM5.1` / `glm` 等便于自动匹配。
3. 选 **温柔风** 发一句短消息：Network 中 generate 应为 **200** 且能流式出字；不应再出现 401 +「对话服务暂时不可用」。
4. 若仍失败：在 ST 终端看 `Chat completion request error`；在 EU 控制台看 `custom secret rotate ok` 或 `writing_style_custom_secret_missing`（内部详情，不对用户展示模型名）。

## 部署

本机保存后重启或刷新即可；网络版需 `git pull` 后重启 Node 并确认 `eu.html` 构建戳为 v125。
