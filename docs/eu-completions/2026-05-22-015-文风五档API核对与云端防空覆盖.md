# 文风五档 API 核对与云端防空覆盖

## 任务

1. 用户确认本地丢失可接受，**云端不要被误覆盖为空**。
2. 核对 EU「文风转换」五档是否各绑定正确 API（OpenRouter / xAI）。

## 文风 → API 映射（`public/eu.html` `EU_WRITING_STYLE_PRESETS`）

| 文风 | id | chat_completion_source | model | 酒馆预设文件 |
|------|-----|------------------------|-------|----------------|
| 现代风 | `modern` | **openrouter** | `deepseek/deepseek-chat-v3-0324` | `文风转换-现代文.json` |
| 文学风 | `literary` | **xai** | `grok-4.3` | （运行时覆盖，无独立预设文件） |
| 温柔风 | `gentle` | **xai** | `grok-4.3` | 同上 |
| 创意风 | `creative` | **xai** | `grok-4.3` | 同上 |
| 重口风 | `explicit` | **xai** | `grok-4.3` | 同上 |

生成链路：`fetchStLiveGenerationProfile` → `resolveEuLiveProfileForGeneration` → `buildStGeneratePayload`（OpenRouter 时带 `openrouter_use_fallback` / `openrouter_allow_fallbacks`）。

## 密钥前提（站长 `wohenziliao` 本机已具备）

- `secrets.json` 中 **active** 的 `api_key_openrouter` 与 `api_key_xai` 均存在 → 五档切换后请求可鉴权。
- 新用户若仅复制 xAI 而未配 OpenRouter，现代风会报缺密钥（见 `2026-05-20-019`）。

## 云端防误删

- `src/endpoints/eu-browser-state.js`：`shouldRejectIncomingConversationKey` 在**磁盘已有非空会话**时，**拒绝**客户端 POST 的空 `{}` conversations（除非 incoming `resume` 带 `clearedAt` 表示用户主动清理）。
- 与前端 v112 `pagehide` 防空写互补：即使本机误推空包，服务端也可 skip 该键。

## 改动路径

## 自测

1. 登录 EU → ☰ → 文风转换，五档卡片应显示 `openrouter/...` 或 `xai/grok-4.3`。
2. 控制台：`dumpEuWritingStyleApiAudit()` 核对 `presets` 与 `activeId`。
3. 切换现代风 / 文学风各发一条，Network `generate` 的 `chat_completion_source` 与 `model` 应切换。
4. 云端已有非空会话时，用旧客户端推 `{}`（或抓包）应见 `skippedKeys` 含 `eu_demo_conversations_<handle>`，磁盘条数不变。
