# 商城整包 push 带回对话云（v92）

## 现象

服务器 SSH wipe 后 `check` 为 2 字节；约 13 分钟后再次 `check` 变为 7444 bytes（2 conv）。v91 已部署仍复现。

## 根因

`euPushMallBrowserStateNow()` 通过 `POST /api/eu/browser-state` 整包上传时，**仍包含** `eu_demo_conversations_*` 等三键。登录后 `scheduleEuMallBrowserStatePush`（约 2.8s）会把浏览器旧 `localStorage` 写回服务器，绕过 v91 对 `scheduleEuConversationCloudPush` 的限制。

## 修复

1. **前端 v92**：`euPushMallBrowserStateNow` 跳过所有对话云键；`euPushConversationCloudNow` 在服务端已 `clearedAt` 且空时拒绝 push 并拉回空本机。
2. **服务端**：`POST /` 与 `POST /conversations` 在磁盘已有 `clearedAt` 时拒绝写入非空会话/旧 resume。

## 路径

- `public/eu.html`（构建戳 `…-v92`）
- `src/endpoints/eu-browser-state.js`

cd /opt/SillyTavern && git pull
