# 任务完成记录 004

## 问题

- 用户反馈：单机稳定版时虽回复短但可完成对话；当前**连基本多轮都异常**（非单纯加长问题）。

## 根因

1. **原生栈 `selectHistoryWithinContextBudget` 早退**：用 `estimate(全部 system + 本句 user)` 与 `budget` 比，一超就 `return []`，**整段对话历史**不会进请求，多轮退化成**单轮**，表现像「没记忆/乱回」。
2. **发请求前已把本轮 user 推入 `conv.messages`**，若不再从 `history` 里去掉**同内容**的最后一条 user，易形成**连续两条 user**（对模型与后处理都不友好）。

## 修改（`public/eu-demo.html`）

- 预算改为：`forHistory = max(0, budget - frontT - userT)`，**仅**用该额度从**新到旧**装 `user/assistant` 历史，**不再**在「前卡一超」时整段历史清空。
- 原生栈分支：若 `sanitize` 后最后一条为 `user` 且与 `userText` 全等，则 `slice(0,-1)` 再算 `historySlice`，避免与末尾 `{role:user, userText}` 重复。

## 自测建议

- 同一会话内连续 3 轮以上，应能保留上下文；若 system/故事书极长仍可能压掉部分旧轮，属预期，可再调 `max_context` 或缩故事书块。
