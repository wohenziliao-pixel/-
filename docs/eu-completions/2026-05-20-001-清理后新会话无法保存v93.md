# 清理云端后新会话无法保存（v93）

## 问题

v92 防「wipe 后被旧 localStorage 推回」过严：云端仍为 `clearedAt` + 空 `{}` 时，用户**新开对话**后每次 `persistConversationRuntime` 触发 push，会被当成旧数据 **block 并清空本机**，表现为聊天当时可见、刷新/换设备丢失。

## 修复

- 新增 `euLocalHasNewChatAfterServerClear`：本机 store 非空、resume **无** `clearedAt`、且有 `conversationKey`/`characterName` → 视为清理后的**新会话**。
- 合并/pull/push 对该情况：**允许 push**，不再 `merge cleared` 覆盖本机。
- 服务端 `shouldRejectIncomingConversationKey`：incoming resume 有会话目标且无 `clearedAt`、`cloudAt >` 磁盘 `clearedAt` 时允许写入非空会话。

构建戳：`20260520-conversation-cloud-save-after-clear-v93`

## 路径

- `public/eu.html`
- `src/endpoints/eu-browser-state.js`

## 部署

本机 `git push` 后服务器 `git pull`、重启 Node；浏览器无痕确认 v93。

## 自测

1. 清理全部历史会话 → check 2 bytes。
2. 新开故事书对话、发几条消息 → 刷新侧栏仍在。
3. `await euDebugConversationCloud()` → `serverBytes` > 2，`localConvCount` ≥ 1。
4. 再登录/换无痕，会话仍在。
