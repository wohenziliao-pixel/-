# 重口风简体中文保障与改写写回修复

## 用户问题

重口风（Euryale）对话后半段英俄乱码：是否模型不合适？是否应保证简体中文？

## 结论

- **重口风**管的是尺度/文风，不是允许乱码；**Euryale 70B** 在长上下文下更易塌缩，与「重口」叠加后偶发半中半乱。
- 产品侧**应保证简体中文**；LLM 不能 100% 物理保证，EU 需检测 + 改写 + 重试。
- 流式发消息路径曾 **丢弃** `rewriteReplyToChineseIfNeeded` 的返回值，且「前半中文后半乱码」未触发改写。

## 改动（`public/eu.html`）

1. 五档文风 system 统一追加 `EU_WRITING_STYLE_LANG_LINE`（简体中文硬性说明）。
2. 重口风 prompt 单独再强调简体中文。
3. `rewriteReplyToChineseIfNeeded`：命中 `isModelGibberishCollapse` 时强制改写。
4. 流式发送后：改写结果写回 `rawStorage`；乱码时再对原文做一次中文改写。
5. `EU_DEGENERATE_RETRY_SYSTEM` 文案覆盖乱码场景。

## 自测

硬刷新 `eu.html`，重口风对吉尔伽美什发长对话；若模型仍乱码，应自动重试或改写为中文（可能多等几秒）。
