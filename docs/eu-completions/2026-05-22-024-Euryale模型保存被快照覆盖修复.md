# Euryale 模型保存后被 GLM 快照覆盖修复

## 问题

用户在「Euryale 70B」配置下选择 OpenRouter 模型 **Llama 3.1 Euryale 70B v2.2**，连接/生成正常，但切换配置后再切回，下拉变成 **Z.ai: GLM 5.1**。

## 根因

1. `buildFullStateFromProfile` 合并时 **`connectionSnapshot` 覆盖 `profile.model`**：快照里残留其它配置的 `openrouter_model`（GLM），切换时优先用了错误快照。
2. 保存快照时只读 `oai_settings`，未读 **当前可见的下拉框**（select2 可能未同步到 `oai_settings`）。

## 改动

`connection-manager/index.js`：

- 切换时 **`profile.model` 优先** 于 `connectionSnapshot` 中的模型字段。
- `captureConnectionSnapshot` 增加 `syncLiveModelFieldIntoSnapshot`，从 `#model_openrouter_select` 等控件读取真实选中值再写入快照与 `profile.model`。
- `applyOpenRouterFieldsFromSnapshot` 对 OpenRouter 配置同样优先 `profile.model`。

## 用户操作（一次）

1. 硬刷新页面。
2. 选中 **Euryale 70B** → OpenRouter 模型选 **Llama 3.1 Euryale 70B v2.2** → 点 **更新配置**（或连接成功后保存）。
3. 切换到其它配置再切回，应仍为 Euryale 模型而非 GLM。
