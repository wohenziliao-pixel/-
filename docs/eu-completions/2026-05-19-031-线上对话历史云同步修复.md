# 线上对话历史云同步修复

## 任务
网络版聊天后刷新/换浏览器历史丢失；本机逻辑已有，线上不生效。

## 根因
1. `euParseBrowserStateResponse` 在整包 `browser-state` **>600KB** 时只做 partial 解析，键列表**不含** `eu_demo_conversations_*`，登录拉取永远拿不到云端对话。
2. 对话上传走 `scheduleEuMallBrowserStatePush` **2.8s 防抖**，关页/刷新时常来不及 `POST`。
3. 商城登录同步 `euSyncMallBrowserStateAfterLogin` **跳过**对话键合并，仅依赖登录初的 pull（易被大快照 partial 漏掉）。

## 修复
### 服务端 `src/endpoints/eu-browser-state.js`
- `GET /api/eu/browser-state/conversations`：只返回对话三键。
- `POST /api/eu/browser-state/conversations`：只合并对话三键；返回 `savedKeys` / `skippedKeys`。

### 前端 `public/eu.html`
- partial 解析键加入对话三键（兜底）。
- `euPullConversationCloudBeforeLoad` 优先调 `/conversations`。
- `scheduleEuConversationCloudPush`（650ms）+ `euPushConversationCloudNow`；`pagehide`/`hidden` 用 `keepalive` 推送。
- 登录商城同步后再合并一次云端对话并 `loadConversationRuntime`。
- 构建戳：`20260519-conversation-cloud-fix-v83`。

## 部署
1. 本机 commit + push `public/eu.html`、`src/endpoints/eu-browser-state.js`。
2. 服务器 `git pull` + **重启 node**。
3. 无痕打开 `https://st.ciyuanji.shop/eu.html`，构建戳含 `conversation-cloud-fix-v83`。
4. 聊 2 轮后 F12 → Network 应有 `POST .../browser-state/conversations` 200；再登录或换浏览器应能续聊。

## 自测
- [ ] 线上发消息后 1 秒内出现 `POST /api/eu/browser-state/conversations`
- [ ] 刷新同浏览器仍见历史
- [ ] 另一浏览器同账号登录能拉到历史（或至少 `GET /conversations` 有 body）
