# 对话云权威清空与防本机回写（v91）

## 任务

清理「我的世界」/ SSH wipe 云端后，浏览器仍显示历史会话；根因是本机 `localStorage` 在云端已 `{}` 时仍会 `push` 回服务器。实现 v91 修复并加冒烟自测。

## 做了什么

1. **云端空 + `clearedAt`**：`euMergeConversationCloudFromServerItems` 返回 `'cleared'`，强制本机三键 `{}` 并写入服务端 resume。
2. **拉取专用接口**：只要 `GET /conversations` 含 `convKey`（含 `'{}'`），不再因「长度≤4」回退整包 `browser-state`。
3. **禁止误 push**：云端已 `clearedAt` 清空时，登录拉取不再 `scheduleEuConversationCloudPush`；仅「云空且无 clearedAt + 本机有数据」才 push（首设备迁移）。
4. **`loadConversationRuntime`**：末尾 `persistConversationRuntime({ cloud: false })`，避免加载即回写云端。
5. **`persistConversationRuntime`**：内存空但 LS 有大缓存且本机有 `clearedAt` 时写空 LS 并 `euWipeConversationCloudNow`；无 `clearedAt` 时只告警、**不 push**。
6. **`migrateLegacyHistories`** / **`tryRestoreLastWorldChatSession`**：有 `clearedAt` 且无会话目标时跳过。
7. **`euDebugConversationCloud`**：改为只读，不再自动 push。
8. 构建戳：`20260519-conversation-cloud-authoritative-clear-v91`

## 用户自测

1. 部署 pull + 重启 Node，无痕打开 `eu.html`，控制台构建戳含 `v91`。
2. 点「清理全部历史会话」→ 侧栏空；`eu-conversation-cloud-check` 三键 2 字节。
3. **再登录/刷新**，check 仍 2 字节，侧栏仍空。
4. 旧浏览器若仍有大 LS：登录后应被云端 `clearedAt` 覆盖清空（无需手动清站点数据）。
