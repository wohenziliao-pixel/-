# GLM5.1 排除 secret-id 导致 EU 无法轮换密钥

## 任务

用户截图：温柔风报「当前文风暂时不可用」，`internal: custom_secret_missing:GLM5.1`；随后兜底出现 `Bad Request`。需说明与酒馆「连接测通」不矛盾的原因并修复。

## 根因

`connectionManager.profiles` 中 **GLM5.1** 的 `exclude` 数组包含 **`secret-id`**。酒馆 Connection Manager 设计为：被 exclude 的字段**不会写入 profile**（编辑时还会 `delete profile[secret-id]`）。因此：

- 在酒馆对 GLM5.1 点 **连接/测试** 可以成功（用的是当时全局激活的 Custom 密钥）；
- 但 profile **没有** `secret-id`，EU v125 无法 `rotate` 到智谱密钥 → `custom_secret_missing`。

**VENICE** 的 `exclude: []`，故有 `secret-id`，控制台可见 `custom secret rotate ok VENICE`。

## 改动

| 路径 | 说明 |
|------|------|
| `data/wohenziliao/settings.json` | GLM5.1 的 `exclude` 移除 `secret-id`，便于之后在酒馆保存密钥绑定 |
| `public/eu.html` | 密钥标签 hints（智谱/glm 等）、双 Custom 密钥时排除 VENICE  id 选另一条；`fetchStLiveGenerationProfile` 不再吞掉带 `euInternalDetail` 的用户错误；构建戳 **v126** |

## 用户操作（必做一步）

1. 强刷 EU，确认 build **`glm-secret-exclude-fix-v126`**。
2. 酒馆 **Connection Manager → GLM5.1**：确认 **Secret** 已勾选进 profile（不再被排除）→ 填 Custom API Key → **连接** → **保存/更新配置**（此时应写入 `secret-id`）。
3. 温柔风再发「你好」，控制台应 **`custom secret rotate ok GLM5.1`**。

## 自测

- 无 `custom_secret_missing:GLM5.1`；generate 非 400/401。
- 不应再出现：先文风错误再 Bad Request 的双红泡（v126 不再静默 `return null` 后走错误兜底）。
