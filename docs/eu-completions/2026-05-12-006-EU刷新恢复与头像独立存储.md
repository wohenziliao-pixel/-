# EU 刷新恢复与头像独立存储

## 任务

用户反馈：**刷新后自定义头像消失**；灌水吧正文仍无图（另见 `2026-05-12-005` 媒体路由）；并询问除账户信息外**灌水区独立于酒馆**是否难做。

## 做了什么

### 头像与刷新

- **原因**：整页刷新后回到登录态，`state.currentUser` 未恢复时若曾用错键读写资料，或 **localStorage 配额** 导致含大段 base64 的整份 JSON 写入失败，头像会丢。
- **自动恢复上次 EU 账号**：`enterApp` 成功后将 handle 写入 `localStorage` 键 `eu_demo_last_user_handle`；`DOMContentLoaded` 时调用 `tryRestoreEuAppSession()` 自动 `enterApp`，无需每次再点「演示进入」。
- **退出 / 切换账号**：`doLogout` 与 `switchTab` 清除该键，避免他人共用浏览器时被静默登入。
- **头像独立键**：`eu_demo_account_avatar_dataurl_<handle>` 单独存 data URL；`eu_demo_account_profile_<handle>` 的 JSON **不再写入** `avatarDataUrl`，减轻主 JSON 体积。加载时优先读独立键，并从旧 JSON 内嵌头像 **迁移** 到独立键。
- **压缩**：上传头像改为长边 **256**、质量 **0.78**，压缩后长度上限 **180000** 字符，降低配额失败概率。
- **文案**：个人资料页说明刷新恢复、同域名访问。

### 与酒馆解耦（产品说明，未改发帖鉴权）

- 灌水数据（`eu-tieba-board.json`、`eu-tieba-media/`）已与酒馆核心数据分离；**发帖/回帖**仍用 `req.user`（酒馆会话）仅因当前实现把「谁发帖」绑定在 ST 登录上。若要 EU 自有会话发帖、只读 ST 展示名，需要新增 EU 鉴权或双轨身份，工作量中等、主要是安全与边界设计，而非「很难」。

## 自测

1. 演示进入 → 上传头像 → **刷新**：应仍停留在应用内且侧栏头像仍在。
2. **退出登录** 后刷新：应回到登录页且不再自动进入。
3. 固定使用 **同一 host**（如始终 `127.0.0.1:8000`），避免与 `localhost` 混用导致 localStorage 不共享。
