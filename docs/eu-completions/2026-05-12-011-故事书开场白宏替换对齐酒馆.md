# 故事书开场白：`{{user}}` / `{{char}}` 宏替换对齐酒馆

## 任务

EU 故事书开场白（`first_mes` 等）中仍显示字面量 `{{user}}`，而酒馆主界面会替换为当前用户/角色名。需对齐酒馆在首条 assistant 上的行为。

## 酒馆侧依据

- `public/script.js` → `messageFormatting`：对首条非系统消息调用 `substituteParams(mes, undefined, ch_name)`，即 `user` 来自全局 `name1`，`char` 来自传入的角色名。
- `substituteParamsLegacy`：`environment.user = _name1 ?? name1`，`environment.char = _name2 ?? name2`。

## EU 改动

- **`public/eu-demo.html`**
  - 新增 **`euMacroCharNameFromActiveStorybook`**：优先当前故事书 `title`，否则从 `state.worldChatName` 去掉「故事书·/-」前缀。
  - 新增 **`euSubstituteOpeningMacros`**：替换 `{{user}}`、`{{char}}`、`{{charIfNotGroup}}`、`<USER>`、`<CHAR>`、`<BOT>`（不实现完整宏引擎）。
  - **`getStorybookGreeting`**：在返回候选文本前做上述替换（`char` 用该书 `title`）。
  - **`buildStorybookRuntimePromptSections`**：对各段 `text` 做替换，避免注入系统提示的 `scenario` 等仍带裸宏。
  - **`buildStorybookWorldInfoText`**：对摘录的条目正文做替换。
  - **`addWorldMessage`**：AI 气泡若仍含占位符（含历史里旧数据），展示前再替换。
  - **`toBackendSafeMessages`**：折叠为首条 system 的「开场 assistant」块在进模型前同样替换。
  - **`EU_CLIENT_BUILD_STAMP`** → `20260512-storybook-opening-macro-subst`。

## 用户自测

1. 使用含 `{{user}}` / `{{char}}` 的 `first_mes` 打开故事书世界聊天，首条气泡应显示画像名（或登录名）与书名，而不是字面量。
2. 开发者模式诊断与 ST 一致前提下，发一条生成，确认 system 折叠块中不再把 `{{user}}` 原样送给模型。
