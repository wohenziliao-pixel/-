# 对话云 push skipped 三键（v95）

## 任务

用户线上已是 v94，控制台出现 `[EU] conversation cloud push skipped keys`（截图里缩写为 push sk），`localBytes`≈4000 但云端仍像没存上。

## 根因

服务端在磁盘 `resume` 仍带 `clearedAt`（清理锁）时，只有 **incoming 包内同时满足** 才放行：

- 非空 `conversations`
- `resume` **无** `clearedAt`，且有 `conversationKey` / `characterName`

实际 push 常出现：

1. **resume 未进 payload**（localStorage 里只有 `{clearedAt, cloudAt}` 或键为空），循环 `continue` 跳过；
2. **resume 仍带 clearedAt**（`euNormalizeResumeBeforeConversationCloudPush` 在「无会话目标」时直接 return，不删锁标记）；
3. 服务端因此 `incomingIsNewSessionAfterServerClear` 为 false，**三键全部被 skip**（`Array(3)`）。

`push ok` 与 `skipped keys` 可交替出现（不同次定时 push）。

## 修复（v95）

### 客户端 `public/eu.html`

- 新增 `euEnsureResumeBeforeConversationCloudPush`：有非空对话 store 时从首条/当前会话**补全 resume**，并删除 `clearedAt`。
- `euPushConversationCloudNow`：push 前必调 ensure；若 payload 仍缺 resume 或含 `clearedAt` 则**本地阻断**并打明确 warn（不再误报 ok）。
- `euLocalHasNewChatAfterServerClear`：store 非空即视为新会话（先 ensure）。
- `euDebugConversationCloud`：增加 `localResume*`、`lastPush`、`hint`。
- `__euLastConvCloudPush` 记录最近一次 push 结果。
- 构建戳：`20260520-conversation-cloud-resume-ensure-v95`。

### 服务端 `src/endpoints/eu-browser-state.js`

- `incomingIsNewSessionAfterServerClear`：除 resume 外，**非空 conv + 非空 character_sessions** 也视为清锁后的新会话。
