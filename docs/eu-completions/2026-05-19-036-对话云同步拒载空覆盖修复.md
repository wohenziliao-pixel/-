# 对话云同步拒载空覆盖修复

## 任务

网络版用户反馈历史记录仍无法跨浏览器/刷新保留；先查本机逻辑并修复根因，给出线上验证步骤。

## 根因（本机代码审查）

1. **拒载 + 空内存覆盖**：云端拉回的快照可达约 3.5MB（`euTrimConversationStoreJsonForCloud`），但 `loadConversationRuntime` 在 **>3MB** 时拒载并清空 `state.conversationStore`。随后任意 `persistConversationRuntime()` 会把 **空对象写回 localStorage 并上传云端**，冲掉服务器已有历史。
2. **推送失败无重试**：`euPushConversationCloudNow` 用裸 `fetch`，403 不重试；`skippedKeys`（超 4MB）时仍可能误判成功。
3. **线上 v86 已含 v83 专用接口**，若仍无历史，优先用 Network / 服务器落盘文件排查是否 push 失败或被空覆盖。

## 改动

- `public/eu.html`（`20260519-conversation-cloud-load-guard-v87`）
  - `EU_CONV_STORE_HARD_REJECT_BYTES` 提至 4MB，与云端单键上限对齐。
  - 超大缓存先 **trim 再加载**，避免拒载。
  - `persistConversationRuntime`：内存为空但 LS 有数据时 **禁止覆盖**。
  - 推送：常规走 `stApiRequest`（CSRF 重试）；`skippedKeys` 视为失败；成功打 `[EU] conversation cloud push ok`。
  - `window.euDebugConversationCloud()` 控制台自检。
- `tools/eu-conversation-cloud-check.mjs`：服务器查 `data/<handle>/eu-mall-browser-state.json` 对话键大小。

## 本机自测

1. `http://127.0.0.1:8000/eu.html` 登录 → 故事书聊 2 轮。
2. F12 Network：`POST /api/eu/browser-state/conversations` → 200，`savedKeys` 含三键。
3. 控制台：`await euDebugConversationCloud()` → `push.ok: true`，`serverBytes` > 0。
4. 无痕/换浏览器同账号登录 → 侧栏会话与消息仍在。
5. 本机：`node tools/eu-conversation-cloud-check.mjs <handle>` 应有 conv 字节数与会话条数。

## 线上验证

1. `git pull` + 重启 node（勿重复 nohup 占端口）。
2. 无痕 `eu.html`，构建戳 **v87**。
3. 聊 2 轮 → Network 见 POST conversations 200。
4. SSH：`node tools/eu-conversation-cloud-check.mjs <用户名>` 应有非 0 字节 conv。
5. 换浏览器登录同账号验收续聊。

仅需 `public/eu.html`（+ 可选 `tools/eu-conversation-cloud-check.mjs`）。
